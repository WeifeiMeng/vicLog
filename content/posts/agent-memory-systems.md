模型没有天然的长期记忆。一次请求结束后，它不会自动记住用户，也不会知道上周完成了什么。对话看起来连续，是因为应用把历史信息重新放进了下一次请求。问题在于：历史会越来越长，而模型的注意力、延迟和成本都有边界。

## 工作记忆：当前任务正在发生什么

工作记忆位于当前上下文中，包括用户目标、最近几轮消息、执行计划、工具结果和仍未解决的问题。它速度最快，也最直接影响下一步决策，但容量有限。

优秀的工作记忆不是完整日志，而是面向当前任务的“运行视图”。一份上千行的构建输出可以留在事件存储中，进入上下文的可能只是错误位置、关键堆栈和已经尝试过的方案。

## 长期记忆：跨会话保留什么

长期记忆通常分为几类：

- **语义记忆**：用户偏好、项目约定、稳定事实；
- **情景记忆**：某次任务发生了什么、为何做出某个决定；
- **程序性记忆**：可复用的步骤、Skill 或工作流；
- **外部知识**：文档、代码、数据库等可重新检索的材料。

并非每句话都值得永久保存。记忆写入需要判断信息是否稳定、是否重复、是否敏感，以及未来是否有明确用途。错误事实一旦进入长期记忆，还可能在多个任务中持续放大。

## 召回不是简单的向量相似度

常见做法是把文本转换为 Embedding，再根据当前查询寻找相似片段。但相关性只是一个维度。实际系统还要考虑时间、来源可信度、所属用户或项目、访问权限、信息新旧以及是否与当前任务冲突。

可以把召回理解为多阶段过程：

```text
当前意图 → 权限与范围过滤 → 关键词/向量召回 → 重排 → 去重 → 注入上下文
```

用户画像等小而稳定的信息可以完整注入；庞大的会话历史更适合按当前问题检索。两种信息不能用同一套 Top-K 逻辑粗暴处理。

## 压缩与遗忘

上下文压缩不是删除旧消息，而是把已经完成的细节转换成更紧凑、仍可追溯的表示。摘要需要保留决定、约束、未完成事项和证据位置，而不是只保留一段流畅叙述。

遗忘也同样重要。用户删除信息后，缓存、向量索引、摘要和派生记忆都应同步失效。否则主记录虽然消失，召回层仍可能把内容重新带回模型。

## 记忆系统真正解决的问题

记忆系统的目标不是让 Agent “什么都记得”，而是在正确的时间提供正确的信息，同时允许信息被修正、过期和删除。它更像数据库、缓存和上下文调度器的组合，而不是一个无限增长的聊天文本框。

MemGPT 提出了类似操作系统分层存储的“虚拟上下文”思路：在有限上下文与外部存储之间移动信息。这种类比很有价值——上下文是昂贵的高速空间，长期存储更大，但每次调入都需要策略。
