大语言模型最自然的使用方式是“一问一答”：用户提供输入，模型生成输出，一次调用到此结束。AI 智能体则多走了一步——它拿到的不是一道只需回答的问题，而是一个需要在环境中逐步完成的目标。

## 从生成文本到改变状态

假设任务是“分析项目最近失败的测试并修复问题”。普通模型可以阅读错误日志并给出建议；智能体还需要查看代码、运行测试、修改文件、观察新结果，必要时调整方案，直到测试通过或发现必须由人决定的事项。

这条链路可以简化为：

```text
目标 → 获取上下文 → 制定下一步 → 调用工具 → 观察结果 → 调整 → 完成
```

其中，大模型负责理解和决策，工具负责连接真实世界，Runtime 负责控制执行过程。没有 Runtime，模型即使“想”调用工具，也没有可靠的权限、状态和生命周期来承载行动。

## 一个智能体至少需要什么

一个可用的 Agent 通常包含五部分：

1. **目标**：定义成功是什么，以及哪些事情不应做。
2. **上下文**：当前任务、历史信息、用户偏好和环境状态。
3. **模型**：进行语言理解、推理、规划与决策。
4. **工具**：读取文件、查询数据、执行代码或调用外部服务。
5. **执行循环**：把每次行动的结果重新带回模型，并决定继续、重试还是停止。

记忆并不等于把所有历史消息都塞进上下文。真正有用的记忆系统需要决定写入什么、何时召回、怎样处理过期和冲突的信息。类似地，工具也不只是函数列表：参数校验、权限边界、超时、幂等和审计都属于 Agent 工程的一部分。

## Workflow 与 Agent 的区别

如果每一步都由代码预先写死，例如“先分类，再检索，最后总结”，它更接近 Workflow。若模型能够根据中间结果动态决定下一步调用哪个工具、是否改变计划，则更接近 Agent。

二者没有高低之分。确定性流程适合边界清楚、风险较高的任务；Agent 适合路径无法提前穷举、需要根据环境反馈调整的任务。生产系统经常把两者组合：外层流程提供约束，局部步骤允许 Agent 自主决策。

## 自主并不等于无限权限

智能体最容易被忽略的问题是“行动半径”。模型可能判断错误，工具也可能返回异常。可靠系统应当默认限制权限：读写分离、危险操作确认、沙箱执行、预算上限、最大循环次数，以及完整的过程记录。

因此，评价 Agent 不能只看它是否完成过一次演示，而要看它在输入变化、工具失败和信息不足时，能否稳定地暴露问题、缩小影响并请求帮助。

## 一句话理解

**大语言模型提供智能，工具提供行动能力，Runtime 把它们组织成一个可控、可观察、可持续运行的系统。** 当这个系统能够围绕目标反复感知、决策和行动时，我们才真正得到一个智能体。
