# Vic Log 个人博客设计规格

日期：2026-09-24

## 目标

构建一个以写作为核心的个人博客前端项目。站点使用 Node.js 生态的 Next.js 框架，视觉语言参考 Joel on Software 的作者侧栏、粗体标题、高信息密度与内容优先布局，但使用独立的品牌、文案和实现。

首版服务于一个简单工作流：作者通过编辑 Markdown 文件维护站点资料和文章，构建过程自动生成首页、文章页、关于页、归档页与 RSS。

## 已确认的品牌信息

- 站点名：Vic Log
- 作者名：Meng Weifei
- 作者简介：暂不填写，由 `content/site.md` 后续维护
- 无头像时使用 `MW` 字母占位；后续添加 `public/avatar.jpg` 后自动使用头像

## 视觉与布局

### 桌面端

页面采用不对称双区域布局：

- 左侧为窄幅作者侧栏，包含站点名、头像或字母占位、作者名、简介和主导航。
- 右侧为主要内容区，首页使用两列文章流展示最新内容。
- 侧栏与正文之间使用细分隔线，正文区域保持充足留白。

### 移动端

- 页面折叠为单栏。
- 作者信息缩短为紧凑页头，导航保持可访问且不遮挡内容。
- 文章卡片改为单列，维持适合阅读的字号和行高。

### 视觉语言

- 暖白色纸张感背景，深灰正文，暗红色作为链接和交互强调色。
- 标题使用粗体无衬线字体，正文使用阅读性良好的衬线字体。
- 日期、分类等元信息采用较小字号和字距，形成编辑部式层级。
- 不复制参考站的名称、照片、文章或其他品牌资产。

## 技术架构

- 框架：Next.js App Router
- 语言：TypeScript
- 样式：CSS Modules 与全局设计变量
- 内容解析：Markdown、YAML frontmatter 和统一的服务端内容读取模块
- 输出方式：静态生成，无数据库、登录或运行时内容后台

项目使用以下职责边界：

- `lib/content`：读取、校验、排序并转换 Markdown 内容。
- `components/author-sidebar`：展示作者和导航信息。
- `components/post-card`：展示文章摘要。
- `components/markdown-content`：渲染文章正文。
- 页面路由只负责组合数据与组件，不直接包含 Markdown 解析逻辑。

## 内容结构

### 站点资料

`content/site.md` 使用 frontmatter 管理结构化资料，正文作为“关于我”的完整内容。初始字段为：

```yaml
---
name: Vic Log
author: Meng Weifei
tagline: ""
avatar: /avatar.jpg
email: ""
github: ""
---
```

`tagline` 为空时，界面显示中性的“简介稍后补充”文案。头像文件不存在时显示 `MW` 字母占位。

### 文章

每篇文章存放在 `content/posts/<slug>.md`。首版字段为：

```yaml
---
title: 把复杂系统讲清楚
date: 2026-09-24
category: 工程
excerpt: 文章摘要。
published: true
---
```

- 文件名是稳定的 URL slug。
- `title`、`date`、`excerpt` 和 `published` 为必填字段。
- `category` 为可选字段。
- `published: false` 的文章不进入公开页面、归档或 RSS。
- 文章按日期从新到旧排序。

## 页面与路由

### 首页 `/`

- 显示作者侧栏和按日期排序的文章列表。
- 桌面端文章列表为双列，移动端为单列。
- 每篇文章显示日期、可选分类、标题、摘要和“继续阅读”链接。

### 文章详情 `/posts/[slug]`

- 显示文章标题、日期、分类和完整 Markdown 正文。
- 提供返回首页和上一篇/下一篇文章导航。
- 不包含评论系统。

### 关于页 `/about`

- 使用 `content/site.md` 正文渲染作者介绍。
- 复用作者侧栏和全站导航。

### 归档页 `/archive`

- 按年份分组展示所有已发布文章。
- 每项显示日期、标题和可选分类。

### RSS `/rss.xml`

- 输出所有已发布文章的标题、摘要、发布日期和永久链接。
- 站点部署地址通过单一配置项提供，避免在内容文件中重复维护。

## 数据流与构建行为

1. 构建时读取 `content/site.md` 和 `content/posts/*.md`。
2. 内容模块校验 frontmatter，过滤未发布文章并按日期排序。
3. Next.js 为首页、关于页、归档页和每篇文章生成静态 HTML。
4. RSS 路由使用同一份已校验文章数据生成 XML。
5. 内容更新后重新构建即可发布，无需迁移数据库或操作管理后台。

## 错误处理

- 缺少 `site.md`、文章必填字段、无效日期或重复 slug 时，构建失败并输出包含文件路径和字段名的错误。
- 可选简介或头像缺失时使用明确的视觉回退，不阻止构建。
- 未找到的文章 slug 返回 Next.js 的 404 页面。
- Markdown 中的外部链接使用清晰的焦点样式；不在首版自动抓取或验证第三方内容。

## 可访问性与响应式要求

- 使用语义化的 `header`、`nav`、`main`、`article` 和 `aside`。
- 所有交互可使用键盘完成，并提供清晰焦点状态。
- 文字与背景满足可读对比度，正文不使用过小字号。
- 在约 360px、768px 和 1280px 宽度下验证布局。
- 尊重 `prefers-reduced-motion`；首版只使用轻微的链接和卡片过渡。

## 验收与测试

- 单元测试覆盖 Markdown frontmatter 校验、发布过滤和日期排序。
- 静态构建必须成功，并生成所有已发布文章页面。
- 验证首页、文章、关于、归档和 RSS 路由。
- 浏览器检查桌面和移动布局、键盘导航、404 与内容回退。
- 检查页面没有阻塞性控制台错误，链接和 RSS XML 有效。

## 首版明确不做

- 登录、评论、搜索、CMS 或数据库
- 在线 Markdown 编辑器
- 标签筛选或分页
- 深色模式
- 访问统计和第三方跟踪脚本
- 自动部署或绑定自定义域名

这些能力可以在内容规模或发布需求明确后独立设计，不影响当前 Markdown 数据结构。
