# Vic Log 文章作者标识设计

## 目标

为每篇文章增加明确的作者信息，并在首页文章卡片、归档文章列表和文章详情页展示作者。写作后台能够从常用作者中选择，也允许输入新作者。

## 内容模型

每篇 `content/posts/*.md` 的 YAML frontmatter 增加必填的非空字符串字段 `author`：

```yaml
author: Vic
```

现有文章统一迁移为 `Vic`。新建文章默认使用 `Vic`。内容加载器和写作后台均拒绝缺失、非字符串或仅包含空白的作者值，避免公开页面出现无作者文章。

作者名称不采用固定枚举，也不新建作者资料文件。`Vic` 和 `Vic Agent` 是当前的常用建议值，但数据模型允许以后直接保存其他非空作者名称。

## 公开页面

- 首页复用现有 `PostCard`，在日期和分类所在的元信息区域显示 `作者 · <作者名>`。
- 归档页的每篇文章条目显示相同作者信息。
- 文章详情页在标题上方的日期和分类元信息区域显示相同作者信息。

作者信息沿用当前次级文字的字号、颜色和间距，不增加头像、作者主页、筛选或新的导航入口。这样可以保持现有暖白纸张、内容优先的视觉方向，并让三个页面的表达一致。

## 写作后台

后台的文章输入、摘要和完整编辑对象均增加 `author` 字段。编辑器在日期和分类附近加入一个带建议列表的作者输入框：

- 默认建议 `Vic`、`Vic Agent`。
- 用户可以选择建议，也可以直接输入其他作者名称。
- 新建文章的初始作者为 `Vic`。
- 读取和保存已有文章时完整保留作者，序列化回 Markdown frontmatter。

作者输入是必填项；空白值在浏览器端和服务端都会被拒绝。现有保存、版本冲突、原子写入和路径限定 Git 提交流程保持不变。

## 兼容与迁移

一次性为当前所有文章文件补充 `author: Vic`，包括当前尚未提交的文章文件，但不改变这些文件的其他 frontmatter 或正文。由于迁移完成后作者为必填字段，无需在运行时长期保留隐式默认值。

站点级 `content/site.md` 中已有的 `author` 仍代表站点资料，与文章级作者字段相互独立。

## 测试策略

- 内容校验：接受非空作者，拒绝缺失、非字符串和纯空白作者。
- 内容加载：解析文章作者，并在排序、相邻文章和分组流程中保留该字段。
- 写作后台：新文章默认作者为 `Vic`；读取、创建、更新和序列化均保留作者；自定义作者可以保存。
- 组件与页面：首页卡片、归档列表和文章详情页均渲染作者信息。
- 回归验证：运行完整测试套件和生产构建。

## 验收标准

1. 每篇现有文章的 frontmatter 都包含 `author: Vic`，其他内容不被改写。
2. 首页、归档页和文章详情页均能看到每篇文章的作者。
3. `/write` 新建文章时作者默认为 `Vic`。
4. `/write` 可选择 `Vic`、`Vic Agent`，也可输入并保存其他非空作者。
5. 后台再次编辑文章不会丢失已保存的作者。
6. 缺失或空白作者不能通过内容校验或后台保存。

## 明确不做

- 不增加作者头像、简介、独立作者页面或按作者筛选。
- 不建立作者配置文件或作者权限系统。
- 不改变站点侧栏中的站点作者资料。
- 不扩展 RSS 或页面元数据中的作者声明；本次范围仅覆盖用户指定的三个可见页面和 Markdown/后台编辑链路。
